## Advisory (non-blocking)
- **[conventions]** PayloadByKind is an exported dead type with no consumers — `/Users/michaeltouboul/perso/claude-agent-manager/.claude/worktrees/loop-response-panel-code-text/src/store/usePanelStore.ts:23`
  export type PayloadByKind is defined and exported but is never imported or used anywhere in the codebase (confirmed by grep across src/ and electron/). CLAUDE.md says 'Don't create type aliases that just rename an existing type — reuse the source type.' PayloadByKind restates information already expressed in the PanelTab discriminated union and the individual *Payload types. It should either be used (e.g. as the constraint for a generic helper) or removed.
- **[accessibility]** OpenInPanelButton invisible on keyboard focus — `src/components/AgentChat/MessageRow/OpenInPanelButton.tsx:30`
  The button uses `opacity-0 group-hover:opacity-100` but has no `focus-visible:opacity-100` (or `focus-within:opacity-100` on the parent). When a keyboard user tabs to this button it remains invisible (opacity 0), so it is effectively undiscoverable and unusable without a mouse. Add `focus-visible:opacity-100` to the button's className so it becomes visible on focus.
- **[accessibility]** BlockShell action toolbar (including new 'Open' button) invisible on keyboard focus — `src/components/ResponseBody/BlockShell/BlockShell.tsx:32`
  The action toolbar wrapper uses `opacity-0 group-hover:opacity-100` with no `focus-within:opacity-100`. The new 'Open' button registered by CodeBlock in this branch (CodeBlock.tsx lines 14–24) inherits this — a keyboard user who tabs to the 'Open' or 'Copy' button sees nothing. The fix is to add `focus-within:opacity-100` to the toolbar div so the whole toolbar appears whenever any child button receives focus. This is a pre-existing issue that is now materially worsened by adding a second action button (Open) that a user might meaningfully reach by keyboard.
- **[ui-promotion]** blockRegistry imports AgentChat domain module into ResponseBody — `/Users/michaeltouboul/perso/claude-agent-manager/.claude/worktrees/loop-response-panel-code-text/src/components/ResponseBody/blockRegistry.tsx:4`
  blockRegistry.tsx imports CAM_ASK_LANG and isValidAskJson from @/components/AgentChat/askPrompt. ResponseBody is already consumed by three unrelated parents (AgentChat/MessageRow/MessageRow.tsx:4, UtilityPanel/TextTab/TextTab.tsx:1, SessionViewer/SessionMessageRow/SessionMessageRow.tsx:3), making it a genuine multi-parent shared component. Pulling in AgentChat-domain symbols (the 'cam-ask' fenced-language token and its JSON validator) creates a circular domain dependency: a would-be generic markdown renderer now has direct knowledge of the AgentChat ask-prompt protocol. CAM_ASK_LANG and isValidAskJson are pure parsing helpers with no React or DOM code; they should be moved to a neutral location (e.g. src/lib/ or src/types/) so ResponseBody can consume them without importing from a sibling feature folder. As long as this import stands, ResponseBody cannot be promoted to _ui/ and the ResponseBody subtree is not domain-free.
