  The group title ('Model') is rendered in a plain `<div>` with no ARIA role. Inside a `role="listbox"`, group headings should use `role="group"` with `aria-label` (or wrap items in a `role="group"` element labelled by the heading). Without this, the 'Model' section header is invisible to assistive technology — AT users cannot tell which group the options belong to.
- **[accessibility]** Editor (combobox input) missing aria-expanded / aria-activedescendant when model picker is open — `/Users/michaeltouboul/perso/claude-agent-manager/.claude/worktrees/loop-slash-model/src/components/AgentChat/AgentChatInput/AgentChatInput.tsx:154`
  The model picker follows the combobox pattern (input retains keyboard focus while a listbox is visible), but the `RichEditor` element has no `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls`, or `aria-activedescendant`. This was a latent gap for slash/mention, but the model picker (which opens without a typed token) makes it a concrete gap: screen readers have no signal that a listbox appeared, no way to identify which option is currently highlighted, and no link between the editor and the popup. The `modelPickerOpen` flag is already available in `AgentChatInput`; it should drive `aria-expanded` (and `aria-activedescendant` should track `menus.activeId`) on the contenteditable div inside `RichEditor`.
